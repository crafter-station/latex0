In the beginning of the project the team wrote a long list of goals and then
spent many weeks arguing about which of them mattered most. Some wanted speed
above all, others cared only about correct output, and a few simply wanted the
code to be pleasant to read. After a while they agreed that correct output had
to come first, because a fast program that prints the wrong answer is of no use
to anyone, and that speed would follow from a clear design. They wrote small
tests for every rule, ran them on every change, and kept a public list of what
still did not work. Slowly the list grew shorter, the tests grew longer, and
the program began to produce pages that nobody could tell apart from the real
thing, which was exactly the point of the whole effort from the very start.
